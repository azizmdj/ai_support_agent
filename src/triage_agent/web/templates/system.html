Math: the decision rule and what the numbers mean

A ticket is drafted only if all of these hold; otherwise it goes to a person:

  1. no escalate rule fired,
  2. the model label is in the taxonomy,
  3. confidence c >= threshold ({{ threshold }}),
  4. the class is not locked,
  5. all template fields exist in the ticket,
  6. the language has a template.

Confidence is self-reported by the model, not a calibrated probability.

  • recall = correct tickets of a class / all true tickets of that class
  • coverage = drafted / in-scope, non-risky tickets
  • wrong_draft_rate = drafts with the wrong class or sub-type / all drafts
  • pii_leak_rate = PII tickets where a seeded value reaches a model call / all PII tickets

Small samples: with 0 failures in n tickets, the 95% upper bound on the true failure rate is about 3/n (the rule of three). For 28 fraud and complaint tickets that is 3/28 = 11%, so "0 drafted" is evidence, not proof.

Engineering: interfaces, states, audit and how to extend
  • Interfaces: TextModel.complete(system, user) for models, TicketSource (fetch new tickets, send an approved reply) for the ticket system, CaseStore for storage (default SQLite).
  • Audit: every step writes an audit row with the config version. Rows hold ids, class names, confidence, hashes and short codes, never message text.
  • Fail closed: if masking fails, no model is called; if every provider fails or answers invalid JSON, the case goes to a person; a missing field or language means no draft; only the approval gate can send.
  • Add a class: a block in pack/taxonomy.yaml, a template per language in pack/templates/, and example tickets in eval/tickets.jsonl. The validator runs on start; then run eval.
  • Add a model: a block in pack/models.yaml for an OpenAI-compatible or Anthropic API, or a new adapter with one complete() method.
